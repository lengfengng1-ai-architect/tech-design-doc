# tech-design-doc

一个 Claude Code / AI 编程助手的 **skill**：技术方案设计文档的演进式协作流程。

从一次真实的"AI 记忆层架构设计"协作中提炼：一份 1100+ 行的设计方案，经过
6 轮多角度审阅、26+ 项修复收敛为可实施终稿。这个 skill 把整个过程固化为
可复用的方法。

## 它包含什么

- **文档结构铁律**：理念前置、工程后置——先回答"为什么这样做"，再回答"怎么做"
- **协作循环**：讨论对齐 → 落稿 → 多角度审阅 → 修订全量同步（残留检查）→ 案例驱动 → 分批提交
- **多角度审阅菜单**：一致性残留 / 正确性 / 场景走查 / 对抗性 / 更优解 / 接口规范 /
  部署拓扑 / 连锁反应 / 主权边界 / 可测试性——设计过程中可**任意时间多次**调用"审阅一下"，
  每次轮换一个主攻角度
- **真问题模式库**：12 类实战中挖出的问题模式检查清单（持久化提示注入、归属错误、
  静默拒绝、删除级联、多副本失效、串行化覆盖、概念错配、新规则语法连锁、自举问题……）

## 安装

```bash
mkdir -p ~/.claude/skills/tech-design-doc
curl -o ~/.claude/skills/tech-design-doc/SKILL.md \
  https://raw.githubusercontent.com/<YOUR_USER>/tech-design-doc/main/SKILL.md
```

## 使用

开始设计任何技术方案文档时引用本 skill；设计中途随时说"审阅一下"，
即按审阅菜单轮换角度执行一轮深度审阅（结论按 🔴真问题/🟠应修/🟡建议 分级）。
